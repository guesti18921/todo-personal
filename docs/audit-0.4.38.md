# TO-DO Personal 0.4.38 — аудит изменений и приложения

Дата: 18 октября 2026.

## Что исправлено

- После успешного запроса восстановления пароля открывается отдельный экран «Проверьте почту» вместо сообщения под формой. Регистрация, вход с неподтверждённым адресом и запрос из открытого блокнота используют тот же стиль с пояснением по действию.
- Убрана оставшаяся от регистрации строка «Создай аккаунт…» над подтверждением. Заголовок поднят и центрирован; адрес и пояснение выровнены по центру.
- Экран запроса из блокнота временно скрывает навигацию и баннеры, которые выталкивали карточку за пределы небольшого телефона. Возврат сохраняет текущий аккаунт и записи.
- Повторные отправки формы во время запроса заблокированы. Запоздавший ответ восстановления не перекрывает уже открытый аккаунт.
- Повторная регистрация с замаскированным ответом сервера больше не запускает бесполезную проверку входа и не обещает отправку нового письма.
- Сохранены светлая палитра, акценты #C38D9E, язык входа по системе и существующие шрифты: Inter на экране входа, Lato в блокноте.

## Проверки

- Логика приложения: 136 тестов, 135 успешно, 1 дополнительный локальный тест с реальными Android SDK-инструментами пропущен, поскольку SDK в этой среде отсутствует. Криптографические проверки одноразового тестового сертификата выполнены настоящим Java jarsigner.
- UI: 96 тестов, включая Google/email, восстановление, двойные отправки, запоздавшие ответы, чужие аккаунты, черновики, синхронизацию, напоминания и офлайн-перезапуск.
- Браузер: 40 вариантов новых экранов без входа, 2 варианта из блокнота, русский/английский, длинные адреса, ошибки сервера, возврат, центрирование и отсутствие переполнения на ширинах 320–1280 px. Дополнительно проверены обычные экраны блокнота на 10 размерах окна и формы входа/регистрации на 6 размерах телефона.
- Автоматические проверки доступности WCAG 2 A/AA и 2.1 AA не выявили нарушений в проверенных состояниях. Скриншоты ключевых состояний просмотрены вручную.
- npm audit для рабочих зависимостей: известных уязвимостей нет.
- Production: прочитаны ограниченные журналы Auth и состояние проблемного адреса; RLS включён на всех публичных таблицах, прямых разрешений браузерным ролям на таблицы push нет.
- Выпускной pipeline повторяет тесты, проверяет SQL-схему и изоляцию аккаунтов, собирает Android и проверяет подпись APK/AAB. Готовые файлы сайта и ресурсы внутри APK сверяются с проверенной локальной сборкой.

## Письма на Timeweb

Указанный пользователем адрес уже был подтверждён ранее. В исследованном сегодняшнем интервале были повторные регистрации этого аккаунта. Время отправки подтверждения не изменилось; запросов восстановления пароля для него не зарегистрировано. Эти попытки не свидетельствуют о недоставке письма сервером Timeweb: новое подтверждение не отправлялось.

Supabase может маскировать повторную регистрацию существующего подтверждённого аккаунта успешным ответом. Интерфейс не должен принимать такой ответ за доказательство отправки письма. Для существующего аккаунта следует использовать вход или «Забыли пароль?».

Яндекс подтвердил повреждение дата-центров в октябре, однако связи с исследованными попытками отправки не установлено. Тестовые письма без отдельного запроса не рассылались; фактическое попадание нового письма во входящие не подтверждалось.

## Оставшиеся ограничения и рекомендация

- Проверка на физических Android-устройствах, реальной клавиатуры, фоновой доставки push и почтовых ящиков не заменяется браузерной автоматизацией.
- В Supabase отключена проверка паролей по базе известных утечек. Это отдельная настройка усиления защиты, не обнаруженная ошибка новой вёрстки. Настройка не менялась. Документация: https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection
- Информационные уведомления «RLS без политик» для push-таблиц ожидаемы: таблицы намеренно доступны только серверным функциям, а не браузерным ролям. Добавление открывающих доступ политик было бы неверным исправлением.
