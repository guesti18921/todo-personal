# Mobile list management

All entries retains the existing task/note/reminder filters. An optional “Deadline and order” section adds overdue, today, tomorrow and no-deadline filters. Filters combine with full-text search. Search handles Unicode canonical accents and trims surrounding whitespace. Sorting is by nearest deadline (undated last, including the year 9999) or latest change; the order preference is saved per account/device and preserves the smart-date preference. Completed entries retain completion-time ordering. Overdue means a date before today, consistent with the existing Today screen.

“Select several” replaces completion circles with explicit selection circles and shows the task/note type on each card. The selected count, action names and “What will change?” explanation make the effects reviewable. “Select all found” selects the currently visible search/filter results only. Changing a filter or search clears selected IDs. Opening an entry, switching section, opening Saving or changing account ends selection. Android Back first exits selection. Cloud refresh waits during selection; a manual cloud comparison remains available after leaving it.

Actions: complete selected tasks, restore selected completed tasks, or move selected active tasks/notes to tomorrow. Notes are never completed. Moving preserves text and time; relative reminder modes follow the new date, independently chosen reminders retain their original date/time, and disabled reminders stay disabled. Already-tomorrow and completed records are skipped. Moving also dismisses the old text date suggestion to avoid presenting a stale inferred date as a new decision.

A batch is prepared and checked before mutation. Tasks and notes are written through one normalized local snapshot, then use the existing conditional cloud upload. If local storage fails, the UI and working store revert the batch and do not show success. Selection remains available for retry. Undo lasts eight seconds and restores all prior fields, including reminders. It checks every record before restoring any: deletion, a newer edit or a changed type refuses the whole undo. A visible message above mobile navigation keeps Undo accessible on long lists. Restoring completed tasks through the normal action leaves reminders off; Undo completion restores their previous choices.

Validation: model tests cover combined filters, Unicode, ordering, scoped actions, reminder preservation/cancellation and stale undo. Storage tests cover one mixed snapshot and storage failure. Compiled interface scenarios cover filters, selection, batch completion/restoration/moving/undo, offline restart, persisted order and failure/retry. These DOM scenarios do not replace a visual check on the owner's phone. No APK is built for this stage.
