# Постоянная подпись Android

Сборка **Build Android signed APK** использует один постоянный ключ из двух
секретов GitHub. Она собирает `app-release.apk`, проверяет подпись и сверяет
сертификат APK с сертификатом ключа. Если ключ не настроен, пароль неверный
или сертификат не совпал, APK не публикуется. Тестовая подпись не подставляется.

Ключ создаётся один раз на компьютере владельца. Новые версии подписываются
этим же ключом; номер версии повышается при каждом обновлении.

## 1. Проверить Java на Windows

Открой PowerShell и выполни:

```powershell
keytool -help
```

Если команда не найдена, установи JDK (например, Temurin 21) или используй
`keytool.exe` из установленной Java/Android Studio. Перезапусти PowerShell после
установки. Установка Android Studio для самого создания ключа не обязательна.

## 2. Создать ключ один раз

Создадим отдельную папку вне проекта. Сначала проверь, что в ней ещё нет ключа:

```powershell
$signingFolder = "$env:USERPROFILE\Documents\TodoPersonalSigning"
New-Item -ItemType Directory -Force -Path $signingFolder | Out-Null
if (Test-Path "$signingFolder\todo-personal-release.p12") { throw "Ключ уже есть. Не создавай новый: используй существующий." }
```

Затем:

```powershell
keytool -genkeypair -storetype PKCS12 -keystore "$env:USERPROFILE\Documents\TodoPersonalSigning\todo-personal-release.p12" -alias todo-personal -keyalg RSA -keysize 3072 -validity 10000 -dname "CN=Todo Personal"
```

Команда попросит придумать пароль и повторить его. Символы при вводе не
отображаются — это нормально. Запомни пароль; он потребуется для одного из
секретов. Формат PKCS12 использует тот же пароль для ключа и хранилища.
Имя ключа `todo-personal` должно остаться именно таким.

Сохрани резервную копию файла `.p12` и пароль у себя. Этот файл содержит
закрытый ключ. Не добавляй его в репозиторий и не отправляй в чат.
Для будущих обновлений нужен тот же ключ, а не заново созданный файл.

## 3. Два секрета GitHub

Открой репозиторий `guesti18921/todo-personal` → Settings → Secrets and variables
→ Actions → New repository secret.

### ANDROID_KEYSTORE_BASE64

В PowerShell скопируй содержимое ключа в нужном формате в буфер обмена:

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("$env:USERPROFILE\Documents\TodoPersonalSigning\todo-personal-release.p12")) | Set-Clipboard
```

В поле Name введи `ANDROID_KEYSTORE_BASE64`, в Secret вставь из буфера обмена.
Нажми Add secret. Base64 — это формат записи, а не шифрование: содержимое
также является секретом. Не вставляй его в код, обычные GitHub Variables или чат.

### ANDROID_KEYSTORE_PASSWORD

Создай второй repository secret с именем `ANDROID_KEYSTORE_PASSWORD`.
Значение — придуманный при создании ключа пароль. Нажми Add secret.

После добавления ключа очисти буфер обмена:

```powershell
Set-Clipboard -Value "Готово"
```

## 4. Сборка и переход со старого APK

Открой Actions → **Build Android signed APK** → Run workflow → Run workflow.
Эта сборка берёт проверенную версию кода, закреплённую конкретным SHA коммита.
При следующем обновлении SHA меняется явно после проверки кода. Выбор ветки
в меню запуска не меняет закреплённую версию исходников. Сборка запускается
вручную и не публикует сайт. Сборка приложения не имеет доступа к рабочим
секретам подписи; отдельный этап получает APK как данные, не скачивает
репозиторий и не запускает npm, Gradle или приложение. Секреты доступны только
фиксированному встроенному обработчику, который вызывает keytool и apksigner.
Результат: artifact **todo-personal-android-signed**, внутри `todo-personal.apk` и файл
`certificate-sha256.txt` с публичным отпечатком сертификата.

Первый APK с постоянной подписью не обновит установленные ранее тестовые APK:
их подпись отличается. Сначала синхронизируй записи и проверь их на сайте,
сохрани черновики как записи, затем удали старое приложение и установи подписанное.
Войди в прежний аккаунт и включи напоминания на этом устройстве заново.

После этого новые APK из **Build Android signed APK**, собранные с тем же ключом
и большим номером версии, должны обновляться поверх приложения.
Перед публикацией проверим это реальным обновлением между двумя сборками.
Сборка **Build Android test APK** остаётся для временных тестов и не подходит
для постоянного обновления установленного приложения.

## Проверено и ещё требуется

Локально проверены: использование одного ключа в повторных конфигурациях,
совпадение сертификата, отсутствие пароля в Gradle, отказ при неверном пароле,
очистка временного ключа при ошибке и отказ при несовпадении подписанта APK.
Проверка APK в тесте использует имитацию `apksigner`; настоящая криптографическая
проверка выполняется установленным Android `apksigner` в сборке GitHub.

Полная подписанная сборка и установка поверх предыдущей подписанной версии
ещё не проверены: сначала владелец должен создать ключ и настроить секреты.
Рабочий закрытый ключ не создавался и не передавался ассистентом.

Официальные справки:
- https://developer.android.com/studio/publish/app-signing
- https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets
