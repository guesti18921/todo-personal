# TO-DO Personal — оформление служебных писем

Оформление v3, 21.10.2026. Оба HTML-шаблона применены в hosted Supabase агентом и повторно открыты после перезагрузки; полное содержимое каждого совпало с файлами. Темы, основные тексты RU/EN и одноразовые ссылки сохранены. Резервная копия предыдущего оформления — previous-2026-10-21-v2/. Обновление APK не требуется.

Вместо узкой обведённой карточки — свободная композиция шириной до 600 px, крупнее текст, компактная кнопка. Длинный адрес одноразовой ссылки больше не выводится: та же ссылка доступна по подписи «Открыть ссылку» / «Open the link».

Светлая тема: фон #F7F3EE, акцент #C38D9E, основной текст #501F3A. В клиентах, поддерживающих prefers-color-scheme, тёмная тема задаёт фон #000000, основной текст #F7F3EE и вторичный #C7BCC2. Фактическое отображение в Яндекс Почте пока не проверено: автоматическая перекраска клиента может игнорировать стили письма.

Проверки: 12 вариантов Go html/template (RU/EN/язык не задан × web/native × два письма), 24 браузерных варианта (два письма × RU/EN × 320/390/1280 px × светлая/тёмная тема). Проверены отсутствие горизонтального переполнения, точный цвет фона и две ссылки действия. Реальные письма в рамках этой проверки не отправлялись.

Доставка: на скриншоте Gmail письмо находилось в спаме с объяснением сходства с ранее распознанным спамом. Это не ошибка отправки. Публичный DNS на 21.10.2026 содержит DKIM Resend, DMARC p=none и SPF для поддомена возвратов send.m1strell.com через Forge. Корневой SPF Timeweb не изменялся. Наличие записей не доказывает Authentication-Results конкретного полученного письма и не гарантирует попадание во входящие. Для окончательной диагностики нужны заголовки свежего письма или проверка домена и события доставки в Resend. Не повышать DMARC и не добавлять второй SPF ради попытки убрать спам.

## Состав

- templates/confirmation.html — подтверждение регистрации.
- templates/recovery.html — восстановление пароля.
- templates/*-subject.txt — соответствующие темы.
- auth-email-patch.json — только две темы и два тела писем, без SMTP-паролей и переключателей Auth.
- previews/ — безопасные образцы RU/EN без настоящих токенов.
- build.py — воспроизводимый генератор всех этих файлов.

Акцент #C38D9E, светлый фон #F7F3EE, текст #501F3A.
Используются таблицы и встроенные стили, без скриптов, внешних шрифтов и картинок.
Простой знак // остаётся видимым при блокировке изображений. В классическом
Outlook некоторые скругления могут стать прямыми, но текст и ссылка сохраняются.

Язык берётся из user_metadata.todo_personal_language: ru → русский, иначе английский.
Этот атрибут уже сохраняется приложением при регистрации и выборе языка.
Почтовый шаблон не может узнать текущий язык системы устройства, на котором
получатель открыл письмо; для старого аккаунта без настройки используется английский.
Язык — только оформление, не правило доступа.

Кнопка и запасная ссылка используют {{ .ConfirmationURL }}.
Нельзя заменять её адресом сайта или {{ .SiteURL }}: это потеряет проверку
одноразового токена и платформенный redirect, включая Android recovery.
Срок действия ссылки не указан числом, поскольку определяется реальными настройками сервера.

## Применение

1. Открыть Authentication → Emails → Templates в существующем проекте.
2. Сохранить текущие темы и тела Confirmation / Reset password для отката.
3. Вставить соответствующие HTML и тему, проверить встроенный Preview, сохранить.
4. Снова открыть оба шаблона и сверить сохранённый результат.
5. В SMTP Settings менять только Sender name на TO-DO Personal; оставить прежние
   сервер, порт, логин, пароль и From email. Проверять эти поля без раскрытия секретов.
6. Тестовые письма отправлять только после отдельного указания адресата пользователем.
   Проверить реально полученные письма и стандартные ссылки подтверждения/сброса.

Шаблоны в GitHub сами не устанавливаются в hosted Supabase; требуется применение
в панели или узкий PATCH /v1/projects/{ref}/config/auth с надлежащей авторизацией.

## Аватарка

Логотип в теле письма и аватарка рядом с отправителем — разные элементы.
BIMI в Gmail требует CMC/VMC и не является бесплатной гарантией показа.
Не покупать сертификат и не менять DMARC на quarantine/reject лишь ради логотипа:
это требует отдельной проверки всех действующих отправителей домена.
Бесплатно можно подготовить изображение для профиля существующего почтового
сервиса, если он это поддерживает, но отображение зависит от почты получателя.
Не создавать новые аккаунты или платные услуги ради этой настройки.
